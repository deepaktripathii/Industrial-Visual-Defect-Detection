# Dataset

## The demo corpus (`data/demo_dataset/`)

Real industrial defect benchmarks are either gated (MVTec AD, NEU-DET) or
gigabytes in size, which makes a reproducible portfolio project awkward. This
repository ships a **procedurally generated, labelled surface-defect corpus**
with the same folder contract as a real dataset:

```
data/demo_dataset/
  train/{good,scratch,dent,crack,stain}/*.jpg
  val/{good,scratch,dent,crack,stain}/*.jpg
  test/{good,scratch,dent,crack,stain}/*.jpg
  splits.json          # path, split, label, sha256, size for every image
```

| Split | Images per class | Total |
| --- | --- | --- |
| train | 40 | 200 |
| val | 10 | 50 |
| test | 14 | 70 |

320 images at 224 × 224 JPEG (~3.9 MB), generated by
`python scripts/generate_demo_dataset.py` with a fixed seed. Every image is
unique because a seed-derived spec is drawn on the plate.

### Classes

| Class | Generation |
| --- | --- |
| `good` | Brushed-metal plate: low-frequency shading, horizontal streaks, grain |
| `scratch` | 1–3 thin bright or dark straight lines at random angles |
| `dent` | Soft elliptical shadow with a highlight on one edge |
| `crack` | Jagged dark polyline with 1–2 branches |
| `stain` | Soft irregular oily-brown blob |

Why synthetic images are acceptable here:

- The project's goal is the **pipeline** (ingestion → transfer learning →
  evaluation → Grad-CAM → API → monitoring), not a leaderboard number.
- The generator is deterministic, so every run and every reviewer sees the same
  data, and the split manifest can prove there is no leakage.
- The defects are visually distinct enough for ResNet18 to learn them in one
  minute on CPU, which keeps the demo and CI cheap.

## Using a real dataset

Point `DEFECT_DATASET_DIR` at any folder with `train/`, `val/`, `test/`
subfolders and one folder per class, with the defect-free class named `good`.
No code changes are required.

Recommended minimums: ~100 images per class for fine-tuning, stratified by
product variant, camera and lighting. Re-run the split manifest afterwards:

```bash
python -c "from defect_detection.data.splits import save_manifest; save_manifest('path/to/dataset')"
python scripts/train.py --data-dir path/to/dataset
```

### About MVTec AD and NEU-DET

- **MVTec AD** is an *anomaly-detection* benchmark: its training split contains
  only defect-free images, and defects appear only in the test split. A
  supervised classifier cannot be trained on `good` vs `defect` from MVTec
  without either a synthetic defect generator or an unsupervised method
  (PaDiM, PatchCore, autoencoders). This project intentionally takes the
  supervised route because the brief asks for ResNet18 classification.
- **NEU-DET** is a labelled steel-surface defect set (crazing, inclusion,
  patches, pitted surface, rolled-in scale, scratches). Its folder layout maps
  directly onto this project's contract after a train/val/test split; it is a
  good next step for a more realistic evaluation.

## Split hygiene

`splits.json` stores a SHA-256 for every image. `verify_manifest` reports:

- images duplicated **across splits** (data leakage),
- files referenced by the manifest that no longer exist,
- per-split class counts.

The training script prints the check before it starts, and the dashboard shows it
on the Dataset page.

## Labels and imbalance

The demo corpus is balanced. Real lines are not: `good` usually dominates, and
some defect types are rare. The trainer computes inverse-frequency class
weights, and the evaluation reports both binary (normal vs defective) and
per-class metrics so a rare defect class cannot hide behind a high average.
